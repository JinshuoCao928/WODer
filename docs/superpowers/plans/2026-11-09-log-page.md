# WODer Log Page v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Log page where athletes add workouts by typing or by a dropdown form built from their movement-library PDF, review each parsed workout as an editable card, save with or without a date, edit saved workouts from History, and log scaled benchmark results.

**Architecture:** Pure data and logic are tested with `npm test`:
- `library.js`: generated from the PDF;
- `benchmarks.js`: hand-written;
- `forms.js`: converts form values ↔ block, plus the scaled check;
- `core.js`: model, validation, summaries and prompts.

A new UI module, `logform.js`, renders the one form used by both Log and History. `log.js` becomes a pending-card list. `app.js` History gains Edit and the Date-unknown group.

**Tech Stack:** Vanilla ES modules, `node --test`, Python 3 + `pdftotext` (poppler) for the one-off extraction script, claude.ai Artifact runtime (`db`, `user`, `sample`).

**Spec:** `docs/superpowers/specs/2026-11-09-log-page-design.md` (extends `docs/superpowers/specs/2026-11-07-workout-designer-design.md`)

## Global Constraints

- **Layouts:** `strength | amrap | fortime | intervals | pr | other`.
- **PR kinds:** `heaviest | fastest | mostReps | farthest`.
- **Format → layout** (spec §4):
  - Strength, Complex → `strength`
  - AMRAP → `amrap`
  - For Time, RFT, Chipper, Ascending Ladder, Descending Ladder, Pyramid → `fortime`
  - EMOM, E2MOM, Tabata, Intervals, Death By → `intervals`
  - Max Effort → `pr`
  - Partner WOD, Team WOD, Buy-In / Cash-Out → `other`
- **Time strings** match `^\d{1,3}:\d{2}(:\d{2})?$`.
- **`date`** is `"YYYY-MM-DD"` or `null`. Undated sessions never enter `recentWindow`.
- **Weight dropdowns:** 2.5 kg steps to 300, or 5 lb steps to 660. A Rx value that isn't on that grid is inserted as an extra option.
- **Dropdown ranges:** minutes 1–60; rounds 1–50; sets 1–20; reps 1–100 or free text; time = minutes 0–120 + seconds 0–59; every 1–5.
- **Old records:** v1 records (blocks without `type`) must still validate, render and open in the editor, as layout `other` with their `format`/`result` strings kept.
- **Rendering:** all rendering uses `h()` / `textContent`. No `innerHTML` with data.
- **Strings:** every new UI string goes in `src/i18n.js` in both `en` and `zh`.
- **Benchmarks:** Rx default = the first value of each standard pair (e.g. Fran thruster `{lb: 95, kg: 43}`).

## Review Focus

1. **Times over an hour** (Murph 1:05:30 typed as 65 min 30 s) must save as `"65:30"`, a valid time, and display unchanged. Test in Task 4.
2. **Format changed after picking a benchmark** (Fran → switch to AMRAP): fields from the old layout must not leak into the saved block. Test in Task 4.
3. **v1 records** (no `type`, free `result` string) still validate, show their result, and round-trip through `formFromBlock` → `blockFromForm` without losing `result`. Tests in Tasks 3 and 4.
4. **kg profile picks a benchmark:** loads come out in kg (Fran thruster 43 kg, inserted as an option even though it's off the 2.5 grid). Test in Task 4.
5. **Undated sessions mixed with dated ones:** sorting puts them last, summaries don't throw, and the PR still counts as `best`. Test in Task 3.

**Interfaces:**
- Produces:
